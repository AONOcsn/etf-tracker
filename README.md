# ETF 投资跟踪

把 `ETF投资跟踪表.xlsx` 的计算逻辑原样搬到一个离线优先的网页应用上。数据只保存在本机浏览器里，没有账号、没有服务器、不上传任何持仓信息。

## 本地运行

```powershell
npm install
npm run dev
```

然后浏览器打开终端里打印的地址（默认 `http://localhost:5173/`，本仓库调试时用的是 `http://127.0.0.1:5180/`）。

首次打开是**空白账本**。建议先在「更多」页确认基础月投、额外预算、历史高点与目标比例，再往「交易」页记第一笔。

其它命令：

```powershell
npm test        # 单元测试（71 项，覆盖全部派生计算）
npm run typecheck
npm run build   # 产出 dist/，部署时才会用到
```

## 页面

底部五个标签，对应原表的工作表：

| 标签 | 对应原表 | 说明 |
| --- | --- | --- |
| 总览 | 总览 | 市值、未实现盈亏、占比偏离、累计买入/到账/分红、额外预算余量 |
| 计划 | 回撤计划 + 月度计划 | 填观察收盘与标普500收盘，自动算档位与本月合计 |
| 交易 | 交易记录 | 逐笔成交，移动加权平均成本与已实现盈亏 |
| 资金 | 换汇记录 + 入金记录 | 三个子页：**换汇 / 入金 / 出金**。人民币→港元→美元按段记录 |
| 分红 | 分红记录 | 税前、预扣税、其他费用，税后自动算 |
| 更多 | 使用说明 | 参数、ETF 清单、**账户与币种清单**、行情更新、备份、问题汇总 |

### 账户与币种可以自己改

「更多」页有**账户清单**和**币种清单**两个编辑器，能增删改名，资金页的下拉实时跟着变。默认是原表用的那套：

- 账户：国内银行 / 香港汇丰 / 嘉信入金中转 / 嘉信证券 / 其他银行
- 币种：RMB / HKD / USD

改名**不会自动改写已有记录**——历史记录仍用旧名称，下拉里会标注「已不在清单」，避免静默改数据。要一并改的话，把那几笔在资金页重新选一次。

### 出金

「出金」是新增的一类记录：资金从账户对外汇出时留痕。它与入金同构（日期、账户、币种、本金、到账、费用、备注），但**不计入总览的「到账 USD」**——那个指标专指真正进入嘉信渠道的美元。出金也不影响持仓成本与已实现盈亏。


## 计划页的月份列表

账本预置了 120 个月（原表的预留范围），但「历史与后续月份」**不会把 120 个空行全列出来**，只显示两类，按时间倒序（最近的在上）：

1. **有内容的月份** —— 你填过观察收盘日／标普500收盘／新历史高／手填额外预算／备注，或当月有真实成交；
2. **当前月，以及之后两个月** —— 方便提前规划。

其余月份不丢，只是不占屏；需要时从「本月计划」进入，或改系统月份后按需编辑。

## 计算口径

与原表保持一致，几个容易被忽略的点：

- **回撤档位**：`回撤 = max(0, 1 − 观察收盘 ÷ 沿用历史高点)`；低于 10% 拿基础额，10%~不足 20% 加 250，20% 及以上加 500。历史高点**只增不减**，当月收盘创新高也会自动上调。
- **额外预算**：只被真实成交消耗，不随反弹或新高回补；用完回到基础额。只有计划、没记成交时不扣。
- **买入用途**：留空等于「定投」。标为「分红再投」或「其他」的买入不计入回撤计划的实际定投，也不会误扣预算。
- **持仓成本**：移动加权平均法，卖出按此前平均成本扣减，差额计入已实现盈亏。用于投资分析；报税请以券商资料为准。
- **到账 USD**：只累计真正进入嘉信渠道的美元——收币为 USD 且收款账户是嘉信证券／嘉信入金中转的换汇，加上到账账户为嘉信证券的 USD 转账。中转步骤不重复加总。
- **检查状态文案**（「待补日期／金额／份额」「请检查输入」「实际加投超剩余预算，请核对」等）沿用原表措辞，便于和原来的红黄提示一一对应。

## 行情更新

「更多」页有一个「更新行情」按钮，会：

1. 更新各 ETF 的现价与价格日期；
2. 把最近已结束交易日的标普500收盘填进当月的回撤计划。

**数据源是腾讯的公开行情接口**（`qt.gtimg.cn` 实时快照、`web.ifzq.gtimg.cn` 日线），这两个端点是实测下来唯一在浏览器里可以直接用的：Yahoo Finance 与 FRED 的响应**不带 CORS 头**，前端 `fetch` 读不到响应体；Stooq 返回反爬页面；Eastmoney 有 CORS 但连接不稳定且取不到美股代码。

实测取到的值（2026-10-05）：VOO 712.32、QQQM 311.40、SMH 633.90、标普500 7773.95。

**隐私**：点这个按钮会让腾讯看到你的 IP 与查询的代码（VOO、QQQM、SMH、标普500）。请求里**不含任何持仓数量、金额或账户信息**，也不消耗你的 API 额度。不点这个按钮，应用完全不联网。

手工在「计划」页填过的月份会被标记，之后点「更新行情」不会覆盖它——对应原表「已完成月的收盘观察不要覆盖」。

## 备份

数据存在浏览器 IndexedDB 里，**不会随仓库同步**。换手机或清理浏览器数据之前，务必在「更多」页导出 JSON 备份。

- **导出 JSON**：完整备份，导入会覆盖本机现有数据。
- **导出 CSV**：交易／换汇／入金／分红四张表，带 UTF-8 BOM，Excel 打开中文不乱码。
- **历史快照**：每次改动后按天自动存一份，保留最近 7 份，误操作后可回滚。

## 在 iPhone 上使用（部署后）

1. 用 **Safari** 打开站点地址（Chrome 无法添加到主屏幕）。
2. 点底部「分享」→ **添加到主屏幕**。
3. 从桌面图标启动即可全屏使用；首次在线打开后，断网也能用。

如果看起来还是旧版本：用 Safari（不是主屏幕图标）打开站点停留几秒，等它完成更新后再重新打开。「更多」页底部的**构建版本**时间戳没变，就说明仍在用缓存的旧版本。

## 开发笔记

### 为什么行情只用一个数据源

一开始设计了多源顺序回退，但实测发现浏览器端可用的源实际上只有腾讯一家。保留一个必然失败的回退链只会掩盖真实错误，所以改成：失败时明确报错并保留旧值，源配置写成数组便于日后扩展。

### 沙箱环境下的两个坑

本机开发时遇到两个与代码无关的环境问题，记录备查：

1. **`npm install` 报 `EPERM`**：npm 默认缓存目录在用户目录下（`%LOCALAPPDATA%\npm-cache`），不在工作区内，写入被拒。解决办法是把缓存指到工作区内：
   ```powershell
   $env:npm_config_cache = "$PWD\.npm-cache"
   npm install
   ```
   该目录已加入 `.gitignore`。

2. **`npm run dev` / `npm run build` 报 `spawn EPERM`**：Vite 在 Windows 上会用管道调用系统命令探测真实路径，受限环境不允许这种子进程管道调用。在**普通终端**里运行不受影响；只有在权限受限的沙箱里才需要放宽权限。

### 单元测试

```powershell
npm test
```

用 Node 内置测试运行器直接跑 `.ts`（`--experimental-strip-types`），进程内执行（`--experimental-test-isolation=none`），不额外引入测试框架。覆盖：加权平均成本、部分卖出、超卖拒绝、档位边界（恰好 10%／20%）、历史高点只增不减、预算逐月消耗与不重置、手填覆盖（含填 0）、90/10 分配、换汇与入金与出金状态、到账美元去重、批次四段余额、腾讯报文解析、CSV 转义与 BOM、以及**数字输入的逐字代入**（专门盯住「填不了 0.01」这类回归）。

行情解析的测试用例用的是**实际抓回来的报文**而不是手写样例，字段位置一旦变动测试会直接失败，不会悄悄算错价格。

> 注意：Node 的测试运行器**认不得 `.tsx`**，所以被测的纯逻辑一律放在 `.ts` 里（例如数字输入规则在 `src/core/numeric.ts`，而不是组件里）。
